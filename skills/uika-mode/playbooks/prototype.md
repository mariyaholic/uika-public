# Prototype

## When

Settle an empirical design fork by observing a small throwaway implementation.

## Phrase hooks

"prototype", "try both approaches", "prove this approach", "which works better"

## Principles

- principle-attack-the-premise
- principle-laziness-protocol
- principle-prove-it-works

## Steps

1. Run the session start: freshness scan, read WORKSTACK.md, confirm harness.
2. State the empirical fork, competing predictions, budget, and deciding check so the experiment can settle the question.
3. Choose an isolated throwaway location and record its boundaries so production and protected files remain untouched.
4. Build the smallest sketches needed to distinguish the alternatives and confirm each sketch runs.
5. Run the deciding check under comparable conditions and record observations for each alternative.
6. Select the supported approach from measured evidence and label remaining inferences or guesses.
7. Record lab findings under the lab README's Findings heading and record retained scratch paths or completed cleanup.
8. Apply `skills/wrap-checklist` and hand off the conclusion with production implementation explicitly unstarted.

## Done when

The fork has a measured answer or a bounded inconclusive result. The prototype does not ship.

## Stop and escalate

- Stop for exhausted budget, unavailable evidence, or approval-dependent work; ask the Manager only about owner decisions.
