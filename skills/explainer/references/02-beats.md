# 02 — The beat table

Teaching has an arc. Write the beat table before any scene code; one row per beat.

| Beat | Job | On screen | Voice |
|---|---|---|---|
| **hook** | earn the next 30 s | one arresting case, no symbols | the question, plainly |
| **intuition** | make the idea feel inevitable | a picture that *is* the idea | why it should be true |
| **name** | give the symbol its meaning | the term appears, tied to the picture | the definition, after the picture |
| **formalise** | state it exactly | the equation, revealed by construction | read the structure, not the glyphs |
| **payoff** | answer the hook | the hook's case, now explained | the answer, evidence-locked |
| **close** | land it | one line summary; hold | the takeaway, then silence |

## Rules
- **Intuition precedes formalism.** A symbol may not appear before the picture that makes it inevitable.
- **One idea per beat.** If a beat needs "and", it is two beats.
- **The hook returns.** The payoff reuses the hook's case; the viewer should feel the circle close.
- **Budget the seconds.** A beat is 5–15 s; nothing over 20 s. Put the number of seconds next to each row so
  the narration can be written to fit.
- **Lock figures before the build.** Every number in the table goes into `evidence/<family>.json`; the
  `Evidence.guard` refuses anything else.
